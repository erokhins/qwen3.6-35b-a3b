# tools/ — provenance of the copied probes

Every file here except `doc_ref_check.py`, `hostmap_probe.cpp`, `pin_hold.cpp`, `pin_pair.sh`,
`quant_scenarios.py`, `gguf_header_types.py`, `gguf_reader.py`, `audit_published_quant.py`,
`build_llama.sh` and
`halogen_gate.sh` (all ten are this
repo's own) is a **verbatim
copy** made on 2026-10-26 from the 0.8B engine repo, so that this project can re-measure and re-gate without
depending on that repo at read time (rule: `pitfalls/60-docs-and-citations.md`).
Keeping the copies pristine means they can be diffed against upstream later; **do not edit them to remove old
references** — record the caveats here instead.

| file | what it measures | caveat when using it **here** |
|---|---|---|
| `gpu_lock.sh` | machine-wide GPU lock (`/tmp/pi_gpu.lock`), acquire/release by TAG, `status` shows a stale holder | unchanged, and intentionally shared with the sibling project so the two repos exclude each other on the one GPU. Check `grep -c gpu_lock <script>` before a caller acquires it (see `pitfalls/50-harness-and-shell.md`) |
| `halogen_gate.sh` | **written here (2026-10-26)**: takes the local `halogen-flash-server` container down for a measurement window and brings it back — admission (`llamacpp:requests_processing`, `/health` `queued`/`in_flight`, the `/tmp/pi_halogen.lock` stream claim), a `PI_PROVIDER=halogen` self-kill guard, a required caller-declared `GPU_LOCK_TAG`, post-stop verification that the 22.62 GiB really went away, and a timed `up` that logs to `devices/evidence/halogen-restart.log` | it **never acquires `gpu_lock`** — the caller must already hold it, or `down` refuses (self-locking driver deadlock, `pitfalls/50-harness-and-shell.md`). Main agent only. The refusal paths are tested; the real stop/start path is **untested** until halogen is free of other sessions. `pause`/`unpause` are EXPERIMENTAL and not policy (`pitfalls/00-measurement.md`) |
| `bw_probe_hip.cpp` | iGPU grid-stride read + copy sweep over blocks × threads, H2D/D2H, size–bandwidth curve | the numbers are model-independent; build `hipcc -O2 -Wl,-rpath,/opt/rocm/lib -o /tmp/bw_probe_hip bw_probe_hip.cpp` |
| `mem_mode_probe_hip.cpp` | allocation modes (`hipMalloc` / `Managed` / host-pinned) + the total device-visible pool ceiling | use it for `DECISIONS.md` D-02 (can a >34 GiB host mapping be read at full speed?) — that is exactly what it is close to |
| `gemm_peak.cpp`, `gemm_common.h` | dense matrix rate at chosen shapes/classes | its docstring quotes the 0.8B's shapes; pass the shapes this engine will actually emit (see `pitfalls/20-rates-and-occupancy.md`, "price the width the engine emits") |
| `kernel_occupancy_probe.cpp` | blocks/CU and wavefronts/CU per kernel, with a canary that proves the query discriminates 0-LDS vs 64-KiB stubs | its embedded table lists the 0.8B's kernel names; re-run it on this project's kernels |
| `launch_overhead_hip.cpp` | per-launch cost floor | dispatch-bound here, so bimodal — always report the spread |
| `bw_probe.py` | CPU-side read/copy bandwidth → decode ceiling | **`--bytes-per-token` defaults to `1.565e9`, which is the 0.8B.** For this model pass `--bytes-per-token 5.89e9` (bf16 active bytes) or the printed ceiling is wrong by ~4× |
| `isa_probe.sh` | ISA/class inventory of a code object (matrix/dot instructions, WMMA roofs) | remember the census rule: name which files it could actually read (`pitfalls/20-rates-and-occupancy.md`) |
| `doc_ref_check.py` | **not a probe — this repo's own tool**: checks that in-repo path cites resolve, that markdown table rows are terminated, and reports how many line-form, cross-repo and bare-`§` cites exist | it walks only `*.md` and exempts provenance blockquotes, so a clean run measures that population and nothing else. A forward cite to a file a plan has not written yet must be labelled `(planned)` immediately after the cite or it stays MISSING — label it, don't loosen the check (`pitfalls/60-docs-and-citations.md`). Run `python3 tools/doc_ref_check.py --strict` before committing a doc change |
| `hostmap_probe.cpp` | **written here (2026-10-26)**: pool ceiling, host-pin sweep, multi-mapping totals, device-vs-pinned A/B — the D-02 measurement | every bandwidth line is checksum-witnessed and prints `MISMATCH` + "NOT A BANDWIDTH RESULT" instead of a number; the unregistered-pointer case (argv[4]=1) faults the queue, so it is opt-in and last |
| `pin_hold.cpp` | **written here (2026-10-26)**: pin N GiB and hold it, so a second process can be run concurrently — the instrument that refuted the "pool is per-process" reading | allocation only: it prints no timing, so it cannot contaminate a measurement window; evidence `devices/evidence/d02-two-process-*.txt` |
| `pin_pair.sh` | **written here (2026-10-26)**: run N concurrent `pin_hold` instances and print the grant/refusal split plus `gtt_used` and MemAvailable | its verdict line names the two hypotheses it is adjudicating; run it blocking with `tools/gpu_lock.sh` held, and keep total pinned bytes well under MemAvailable — 2×24 GiB next to halogen's 23.5 GiB is the edge of comfortable |
| `gguf_header_types.py` | **written here (2026-10-26)**: HTTP-Range-reads a GGUF header and tabulates the ggml type actually stored per tensor family, with byte totals | answers "what quantization is this file?" without downloading it. Fails loudly rather than printing a partial table (a truncated width map reads like a complete one); `BOOL` is one byte; unknown type ids abort the run rather than counting as zero bytes. **Widths are no longer hand-typed here** — they come from `ggml_block_geom.py`, and the width table prints only after `sum(row_bytes) + data_start == file size` has been checked against the file (local size, or the remote `Content-Range`); a mismatch aborts and a source that reports no size prints an explicit NOT-CHECKED banner. Evidence: `quantization/evidence/q4km-published-width-map-2026-10-26.md` |
| `quant_scenarios.py` | **written here (2026-10-26)**: family census from `checkpoints/*.config.json` validated against the index `total_size`, then residency + per-token + tok/s ceilings per quantization policy | ceilings are bytes ÷ bandwidth, not engine measurements; `--census` must print a delta against `total_size` of a couple of %, otherwise the shapes drifted (`checkpoints/README.md`). Since 2026-10-26 it aborts before printing any policy row unless every width a policy can spend (4.5 / 8.5 / 16 / 4.25 / 6.5625) is a width the pinned ggml header derives — which is how the retired hand-typed Q5_K 5.5625 could no longer be typed back in. No policy row uses Q5_K, so policy A's 19.59 GiB / 2.331 GiB-per-token did not move when that row was corrected |
| `ggml_block_geom.py` | **written here (2026-10-26)**: reads block element counts and byte sizes out of `engines/llama.cpp/ggml/src/ggml-common.h` at run time (struct member sums, including inline `union { struct {...} }` accessors, cross-checked against each struct's own `static_assert`, macros evaluated by a small recursive-descent expression parser) and is the single source of width arithmetic for `gguf_reader.py`, `gguf_header_types.py`, `quant_scenarios.py` and the audit | written because two tools hand-typed the same width table and one row was wrong (Q5_K at 5.5625 bpw where the struct is 176 B/256 = 5.5). A struct whose member sum disagrees with its own `static_assert` aborts the run; a struct the scanner cannot read (nested unions it does not model) is reported and never priced. Element-count-per-block is a claim about the type, not a header reading, and is witnessed instead by `check_file()`'s size identity over all 733 tensors. `--emit` writes `quantization/evidence/audit-block-geometry-2026-10-26.md`; `--check PATH` runs the identity against a real file |
| `gguf_reader.py` | **written here (2026-10-26)**: stdlib GGUF header parser + F32/Q8_0/Q4_K/Q5_K/Q6_K dequantizers + reference quantizers for the floor probe, transcribed from `engines/llama.cpp` `ggml/src/ggml-common.h` and `ggml/src/ggml-quants.c` at `d327bf1f` | it gates the data section: `Gguf.open_data()` raises unless the caller holds the selftest token, so a section that has not proven the gate cannot read a value byte. The quantizers are for sizing a band ONLY — the bf16 checkpoint is the comparison reference, never this file's own decode (`pitfalls/30-numerics.md`). Block geometry is witnessed by `sum(row_bytes) + data_start == file size`: Q5_K is 176 B/256 elts = **5.5 bpw**, not the 5.5625 in `gguf_header_types.py`'s table |
| `audit_published_quant.py` | **written here (2026-10-26)**: PLAN step 1 as a gate — sha/revision identity, shard-vs-census reconciliation + `mtp.*` extraction, structure pass over every tensor record, zero-tolerance exactness pass, floor probe, dequant comparison, injection matrix, shared-storage check, pin, and the markdown summary | the ordering is load-bearing and self-evidencing: `--selftest` must pass (and its hashes stay current) before any section may read a value byte, and every refusal and first-read is appended to `quantization/evidence/audit-ordering-2026-10-26.log`. Sections refuse to run out of order (`--dequant` before `--floor-probe` exits non-zero). CPU only, prints no timing (`pitfalls/00-measurement.md`); `--all` runs 1.1–1.6 then the summary |
| `build_llama.sh` | **written here (2026-10-26)**: reproducible HIP (`gfx1151`) build of the pinned oracle checkout `engines/llama.cpp` @ `d327bf1f0780f87b8c01b367b61853b0c291d7c4` (tag `b11869`) — `GGML_HIP=ON`, `Release`, shared libs, one arch, targets `llama-cli` + `llama-quantize` — plus a 17-check integrity gate over the artifacts | the commit guard is the point: it refuses a checkout at any other revision (exit 3; `BUILD_LLAMA_PINNED_COMMIT` exists only to witness that refusal firing) and refuses a checkout with modified tracked files (exit 4), because the verdicts in `quantization/evidence/llama-cpp-build-and-flags-2026-10-26.md` are claims about that revision. The gate's expected-check count is a constant the gate must agree with, so a check that stops running is red, not shorter. Compiles only — no model load, no device memory, no timing, and it takes no lock (`--list-devices` and everything above it belong to the main agent). Non-obvious flags it pins: `-Wl,-rpath,/opt/rocm/lib` on **both** the exe and the shared link lines, `GPU_TARGETS`+`AMDGPU_TARGETS`+`CMAKE_HIP_ARCHITECTURES` all three, and `LLAMA_USE_PREBUILT_UI=OFF` (otherwise the build downloads the UI from Hugging Face). **`cmake` is not on PATH on this box** — install one (`uv tool install cmake`) or pass `CMAKE=` |
